### [用电压毛刺绕过熔丝，部分解锁 A100 级 CMP 矿卡](https://blog.kate.land/posts/using-voltage-glitching-to-unlock-the-a100/) ⭐️ 8.0/10

一篇动手博客展示了如何用电压毛刺绕过基于熔丝的硬件限制，从而部分解锁一张 A100 级 NVIDIA CMP 矿卡。文章把反向工程、电气操作以及 CUDA/驱动层面的问题结合起来，但结果来自作者的单次实验，并没有给出可稳定复现的通用方案。

hackernews · lae · 11月11日 10:48 · [社区讨论](https://news.ycombinator.com/item?id=50451903)

**「背景」** CMP 170 HX 是 NVIDIA 基于 GA100（与 A100 同代）的矿卡，出厂时通过熔丝关闭了部分显存和 SM；一份公开的社区记录称，已有玩家尝试用软件和刷 VBIOS 的方式将其解锁到 64 GB 显存和 74 个 SM。另有报道指出，这类芯片在物理上可能搭载远超标称容量的 HBM，例如 A100 80 GB 型号实际配有 96 GB，说明被熔丝屏蔽的资源未必不存在。

**「实际影响」** 对持有同类矿卡、具备硬件实验能力的人来说，这项演示说明被熔丝禁用的资源有可能通过物理手段恢复；但作者只实现了部分解锁，而且电压毛刺属于硬件改动，不能据此认为已经存在可供日常使用的通用解锁方法。

**「社区讨论」** 评论区里，有人惊叹曾把 80GB HBM 装到芯片上却关闭九成资源，也有人反驳说，更可能是芯片制造缺陷太多才被降级为矿卡，而不是单纯出于市场分层。另有读者称正尝试用软件方式解锁 CMP 170HX 的 80GB 但两周未成功，并指出这篇博客针对的是 8GB 型号、熔丝方案风险更高。

### [glibc 考虑新增调优项禁止不支持 ASLR 的程序](https://lwn.net/Articles/1105134/) ⭐️ 8.0/10

LWN 报道，Node.js 的 Brotli 解码器出现缓冲区溢出漏洞，而官方 Linux 二进制文件的构建方式导致地址空间布局随机化（ASLR）无法启用，使阻止缓冲区溢出升级为远程代码执行的主要防护之一失效。作为回应，glibc 正在考虑新增一组 tunable 设置，让管理员可以禁止不支持 ASLR 的程序运行。LWN 指出，这是值得欢迎的加固措施，但可能并未解决根本问题。

rss · LWN.net · 11月11日 14:35

**「背景」** ASLR 通过随机化进程的地址空间布局，使缓冲区溢出更难被稳定利用；而 Linux 程序启动时的地址布局由动态链接器参与安排，因此相关加固落在 glibc 的动态链接器上。glibc 的动态链接器已经提供 tunables 机制，可在启动时调整运行时行为并列出支持的选项，此次提议是在这一机制上增加新的限制开关。

**「实际影响」** 对使用官方 Node.js Linux 二进制或自行捆绑 Brotli 的团队来说，短期应对仍是升级到修复版本，而不是等待 glibc 的新限制：NVD 列出的修复版本包括 1.0.10、1.1.1 或 1.2.1，且漏洞位于 Brotli 库本身，凡捆绑同一解码器的软件都受影响。若管理员启用 glibc 正在考虑的 tunable 设置，那些不支持 ASLR 的旧程序可能被拒绝运行，因此部署前需评估兼容性；该设置目前仍是拟议措施，不能替代补丁。

### [AWS 官方本地模拟器由 AI agent 构建](https://github.com/aws/aws-emulator) ⭐️ 7.0/10

AWS 在 GitHub 上公开了官方 aws-emulator 项目，目标是在本地克隆多项 AWS 服务，让开发者无需配置付费 API key 就能运行测试。该项目用 Rust 编写，项目介绍称大量自主 AI agent 在最初三周提交了 29,684 次 commit；目前在 macOS 和 Windows 上运行需要 Docker。项目文档明确警告不要用它测试 IAM 策略、资源策略、KMS 密钥策略、跨账户或跨区域访问等安全控制，HN 评论也质疑它究竟是可维护的产品还是实验。

hackernews · super\_linear · 11月11日 18:21 · [社区讨论](https://news.ycombinator.com/item?id=50456631)

**「背景」** 本地云模拟器的作用是在开发机上复刻 AWS 服务的 API 行为，使应用能用与真实 AWS 相同的 CLI 和 SDK 命令进行测试，而不必连接云端账户。AWS 于 2026 年 11 月 11 日发布免费开源的 Rust 版 AWS Emulator，基于 438 个 AWS API 模型覆盖 200 多个服务，代码由自主 AI 代理编写和测试。

**「影响」** 对想把 AWS 调用放进本地 CI 的开发者，当前在 macOS 和 Windows 上至少要先安装 Docker，而且模拟器通过并不等于 IAM、KMS 或跨账户权限配置正确；这类安全测试仍需真实 AWS 环境或其他专门工具。

**「社区讨论」** 评论区的核心分歧是项目是否会被 AWS 长期维护：CharlieDigital 因状态不明而推荐 Floci 和 Testcontainers，wg0 则认为没有 AI agent，AWS 不会为这么多服务投入建设这种模拟器。另有评论引用安全文档，提醒它不能替代 IAM/KMS 等权限测试，也有 Amazon 员工称其“若维护得当”价值很大。

### [Safe Sand：WebGL2 沙粒模拟与程序化音效](https://av.github.io/safe-sand/) ⭐️ 7.0/10

一个名为 Safe Sand 的 WebGL2 浏览器沙粒模拟演示在 Hacker News 上引发讨论：用户可在浏览器中倾倒不同沙种，并获得随沙种变化的程序化音效。评论者称手机端摇晃交互更自然，也有人指出石块移动过快、需要更多摩擦，并提醒倾倒时的声音可能过大。社区已找到并分享其 GitHub 源码仓库 av/safe-sand。

hackernews · everlier · 11月11日 13:39 · [社区讨论](https://news.ycombinator.com/item?id=50453288)

**「背景」** WebGL2 是浏览器中的 GPU 图形接口，使交互式物理模拟无需安装插件即可运行。该演示的代码仓库称，它在 GPU 上以毫米和 9.81 m/s² 为单位模拟约 10 万至 46 万颗沙粒。

**「影响」** 对面向公众的浏览器交互演示而言，最直接的改进点是默认静音或在“倾倒”前给出音量提示，否则戴耳机的用户可能被突然出现的大音量吓到。

**「社区讨论」** 多条评论围绕声音：有人要求默认静音或在“倾倒”前提示音量；另一人注意到不同沙种的音色确有差异，但认为声音并非完整物理建模，而是由少量参数、随机化和对流速的响应合成。移动端用户建议摇晃手机体验，并有人指出石块运动过快、需要更多摩擦。
