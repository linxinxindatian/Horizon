### [Rust 1.100 发布：稳定 never 类型与自定义分配器](https://blog.rust-lang.org/2026/11/12/Rust-1.100.0/) ⭐️ 8.0/10

Rust 1.100.0 于 2026 年 11 月 12 日发布，稳定了 never 类型和 Allocator API 的核心部分，并让 Cargo 开始报告未使用的依赖。官方发布说明将这几项列为该版本的主要变化；这些能力此前属于不稳定特性，现在进入稳定版工具链。对于直接管理内存分配或依赖 Cargo 检查依赖使用的 Rust 项目，升级后即可使用相应功能。

hackernews · mbStavola · 11月12日 18:39 · [社区讨论](https://news.ycombinator.com/item?id=50472038)

**「背景」** \`\!\`（never）类型用于表示永远不会正常返回的计算；据发布说明，它历经约十年和五次失败的稳定化尝试，直到 Rust 1.100 才稳定。本次同时稳定 \`allocator\_api\` 的核心部分 \`Allocator\` trait，使库作者能为 \`Vec\` 和 \`Box\` 等标准库类型定义自定义分配器；这是 Rust “Allocators 1.0” 项目目标的基础。

**「影响」** 对于使用 Cargo 的团队，Rust 1.100 提供的依赖冷却（min-publish-age）默认不启用；若希望解析器延迟采纳新发布的依赖版本，需在 \`.cargo/config.toml\` 中显式配置，否则项目仍会立即选用新版本，已存在于 \`Cargo.lock\` 的版本则不受该窗口限制。

**「社区讨论」** 评论者普遍欢迎此次发布，nirinor 特别提到 never 类型、自定义分配器、依赖冷却配置（RFC 3923），以及 cargo install 默认使用 .crate 包内锁文件、--locked 变为无效选项等变化；ammar\_az 还指出 bool::toggle\(\)、Box::map\(\)、str::trim\_prefix\(\) 等稳定 API 未出现在博客正文中。jadbox 则质疑编译器是否变快，并抱怨编译耗时以及每天需要 cargo clean 清理大量临时文件。

### [ISO 首次拒绝批准 C++26 标准文件](https://lwn.net/Articles/1105400/) ⭐️ 8.0/10

ISO 于 10 月 23 日首次拒绝批准工作组 WG21 提交的标准文件，使 C++26 的前景变得不确定。争议集中在拟议的 contracts 特性上，该特性会为函数签名增加前置条件和后置条件。此前，自 1998 年以来，ISO 已批准七个 C++ 语言修订版。此次拒绝的具体后果和后续处理目前尚未明确。

rss · LWN.net · 11月12日 14:29

**「背景：契约特性与 DIS 意见流程」** 契约（contracts）是为函数签名附加前置条件和后置条件的语言特性，相关设计讨论已跨越多个标准版本，争议集中在具体语义，以及一个特性在标准化前需要多少实际部署验证、是否应带着已知缺口先发布首个版本（tool-2-2）。在 ISO 投票前，各国家团体（national bodies）会就草案国际标准（DIS）提交意见，而 WG21 按 ISO/IEC 指令须逐条处理；一份题为《Do not remove Contracts from C++26》的 WG21 文件（P4433R0）即据此表示将在会议上回应所有针对 C++26 DIS 的国家团体意见（tool-2-1）。

**「影响」** 对使用或跟踪 C++ 标准的开发者来说，直接后果是 C++26 的发布状态和 contracts 特性的最终形态都不再确定；在 ISO 与 WG21 说明后续流程前，围绕该特性的实现和迁移决策需要保留余地。
